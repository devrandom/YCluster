# CDI spec regeneration on GPU VM hosts

## Symptom

`podman run --device nvidia.com/gpu=0 ...` fails with one of:

- `unresolvable CDI devices nvidia.com/gpu=0`
- `failed to load CDI Spec: failed to unmarshal CDI Spec: error unmarshaling
  JSON: json: unknown field "additionalGids"`
- `failed to load CDI Spec: invalid version "0.7.0"`

`nvidia-smi -L` on the host works fine — the GPUs are visible. CDI is the
broken layer between podman and the GPU devices.

## Root cause

`/etc/cdi/nvidia.yaml` is generated by `nvidia-ctk cdi generate` against
whatever GPU set was visible at generation time. It goes stale when the
host-visible GPU set changes (driver upgrade, vfio→nvidia rebind, more
or fewer cards in the host driver). podman 4.9.3 can't parse CDI 0.7.0
specs (the current nvidia-ctk default) — its parser rejects
`additionalGids` and refuses any version above 0.6.0.

Two failure modes overlap:
- **Stale device set**: spec lists 8 GPUs from a pre-vfio state; only 4
  exist on disk now → CDI fails to stat /dev/nvidia4..7.
- **Version mismatch**: spec is current but written as 0.7.0; podman
  rejects the format.

## Procedure

```bash
# 1. Regenerate the spec (only the post-rebind device set matters):
sudo nvidia-ctk cdi generate \
  --device-name-strategy=index \
  --output=/etc/cdi/nvidia.yaml

# 2. Downgrade to a version podman 4.9.3 can parse:
sudo sed -i 's/cdiVersion: 0.7.0/cdiVersion: 0.6.0/' /etc/cdi/nvidia.yaml

# 3. Strip the `additionalGids` field (post-process; nvidia-ctk has no
#    flag to suppress it, and podman 4.9.3 rejects it):
sudo python3 -c "
import re
with open('/etc/cdi/nvidia.yaml') as f: c = f.read()
c = re.sub(r'^        additionalGids:\n(?:            - \d+\n)+', '', c, flags=re.MULTILINE)
with open('/etc/cdi/nvidia.yaml', 'w') as f: f.write(c)
"

# 4. Verify: the smoke test should now report a GPU:
sudo -u dev podman run --rm \
  --device nvidia.com/gpu=0 --group-add keep-groups \
  docker.io/voipmonitor/vllm:lucifer nvidia-smi -L
```

If step 4 still fails with `unresolvable CDI devices`, the spec is
structurally broken — re-check with
`podman --log-level=debug run --device nvidia.com/gpu=0 ...` and look
for the specific parse error.

## When to run this

- After a driver upgrade (host driver or in-VM driver changes the
  visible GPU set).
- After a vfio→nvidia rebind (some/all GPUs come back to the host).
- After `ycluster vm launch` / `ycluster vm stop` on a GPU VM host
  (passthrough set changes).
- Whenever a podman CDI smoke test on a GPU host starts failing for
  no obvious reason — `/etc/cdi/nvidia.yaml` is the first place to
  look.
