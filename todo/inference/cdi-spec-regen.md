# CDI spec regeneration on GPU host (driver / vfio rebind)

Stale `/etc/cdi/nvidia.yaml` after a driver upgrade or a vfio→nvidia
handover causes podman CDI to fail with
`failed to inject devices: failed to stat CDI host device
"/dev/nvidia<N>": no such file or directory` even though nvidia-smi
shows the GPU. Hit during a recent DS4 launch on a GPU VM host: the
spec listed 8 GPUs (mapping nvidia.com/gpu=0 → /dev/nvidia4), but
only the 4 host-visible cards existed on disk (/dev/nvidia0-3); the
spec hadn't been refreshed since vfio-pci took 4 GPUs for an EXL3 TR3
VM.

## Current state

`nvidia-cdi-refresh.service` is disabled cluster-wide
(`clear-benign-failed-units.yml`) and `nvidia-cdi-refresh` isn't even
installed on this image. After a driver upgrade or a vfio→nvidia
rebind, the CDI spec must be regenerated by hand:

```bash
sudo nvidia-ctk cdi generate --output=/etc/cdi/nvidia.yaml
```

`gpu-passthrough-bind.sh.j2` binds GPUs to vfio-pci on boot but
doesn't regenerate CDI, so the spec stays stale from whatever the last
manual generation produced.

## Proposed

1. Wire CDI regeneration into `gpu-passthrough-bind.sh.j2`:
   - When `host_nvidia > 0` after the rebind (some GPUs stayed on the
     host), run `nvidia-ctk cdi generate --output=/etc/cdi/nvidia.yaml`
     to match the post-rebind device set.
   - When `host_nvidia == 0` (all GPUs passed through), `rm -f
     /etc/cdi/nvidia.yaml` — a stale spec advertises ghost GPUs that
     will fail every smoke test.
2. Make it idempotent: only regenerate when the existing spec's
   device list doesn't match `ls /dev/nvidia{0..N}` after the rebind.

## Trade-off

CDI generation has to run after the vfio-pci rebind completes — if it
runs against a half-bound state (some GPUs still in nvidia, some in
vfio), the spec is wrong again. Cheap to re-run, so the simplest path
is: `gpu-passthrough.service` calls `nvidia-ctk cdi generate` as its
last step.

## Before rollout, verify

- A GPU VM host with 4 host-visible + 4 vfio-pci (today's state on
  the EXL3 TR3 host): generate, confirm nvidia.com/gpu=0 →
  /dev/nvidia0, not /dev/nvidia4.
- Same host after `ycluster vm stop <exl3-vm>` + manual vfio unbind
  (host_nvidia=8): regenerate, confirm nvidia.com/gpu=0 →
  /dev/nvidia0.
- The DS4 setup script's GPU smoke test passes against the fresh
  spec.
